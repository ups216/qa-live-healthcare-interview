## 1. 概述

### 1.1 背景

当前系统中，患者进入问诊页面（`/consultation`）时，采用"姓名 + 生日"的身份验证方式。该方式存在以下问题：

1. **安全性极低**：姓名和生日是公开信息，任何人都可冒充患者查看问诊记录
2. **身份不可靠**：同名同生日概率虽低，但无法保证唯一识别
3. **与医生登录不对称**：医生已采用用户名+密码登录，患者却使用简单验证，体验和安全性不一致
4. **数据存储隐患**：患者数据目前存储在前端 JSON 中，任何人都可查看全部患者信息

### 1.2 目标

1. 将患者身份验证方式从"姓名+生日"改为"用户名+密码"登录，提升系统安全性
2. 患者数据后端化，登录验证由后端 API 完成，前端不再存储敏感数据
3. 保持与医生登录流程一致的用户体验
4. 支持新患者注册功能

### 1.3 范围

| 范围 | 说明 |
|------|------|
| 包含 | 患者登录页面改造、患者注册功能、后端患者登录/注册 API、数据库 patient 表增加 username/password 字段、前后端联调 |
| 不包含 | 医生登录改造（已有用户名密码）、其他页面的国际化、问诊流程逻辑变更 |

## 3. 功能需求

### 3.1 功能清单

| 编号 | 功能名称 | 描述 | 优先级 |
|------|----------|------|--------|
| F-01 | 患者登录 | 患者通过用户名+密码登录系统 | P0 |
| F-02 | 患者注册 | 新患者通过用户名+密码+姓名+生日+手机+性别注册账户 | P0 |
| F-03 | 登录状态保持 | 登录后刷新页面仍保持登录状态（Session/Token） | P1 |
| F-04 | 退出登录 | 患者可主动退出登录，返回登录页 | P0 |

### 3.2 功能详细描述

#### F-01：患者登录

**描述**：患者在问诊页面输入用户名和密码进行身份验证，验证通过后进入问诊主界面。

**前置条件**：
- 患者已注册账户
- 后端服务（qa-service-user）正常运行

**操作流程**：
1. 患者访问 `/consultation` 或 `/consultation/:doctorUsername`
2. 页面显示登录表单，包含用户名和密码输入框
3. 患者输入用户名和密码，点击"登录"按钮
4. 前端调用后端登录 API 进行验证
5. 验证成功：显示患者问诊主界面，展示历史问诊记录
6. 验证失败：显示错误提示"用户名或密码错误"

**业务规则**：

| 规则编号 | 规则描述 |
|----------|----------|
| R-01 | 用户名和密码均为必填项 |
| R-02 | 密码在传输和存储时需加密处理（后端 BCrypt 加密存储） |
| R-03 | 登录失败时不得提示具体是用户名错误还是密码错误，统一提示"用户名或密码错误" |
| R-04 | 同一用户连续登录失败不做限制（面试项目，简化处理） |

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| 用户名不存在 | 提示"用户名或密码错误" |
| 密码错误 | 提示"用户名或密码错误" |
| 后端服务不可用 | 提示"网络异常，请稍后重试" |

---

#### F-02：患者注册

**描述**：新患者在登录页面点击"注册"链接，跳转到注册表单，填写信息后创建账户。

**前置条件**：
- 后端服务（qa-service-user）正常运行
- 数据库中该用户名未被占用

**操作流程**：
1. 患者在登录页面点击"没有账号？立即注册"链接
2. 页面切换为注册表单，包含：用户名、密码、确认密码、姓名、生日、手机号、性别
3. 患者填写信息后点击"注册"按钮
4. 前端调用后端注册 API
5. 注册成功：自动登录并跳转到问诊主界面
6. 注册失败：显示具体错误信息（如"用户名已存在"）

**业务规则**：

| 规则编号 | 规则描述 |
|----------|----------|
| R-01 | 用户名必填，长度 3-20 位，仅允许字母、数字、下划线、连字符 |
| R-02 | 密码必填，长度 6-20 位 |
| R-03 | 确认密码必须与密码一致 |
| R-04 | 姓名必填 |
| R-05 | 生日必填 |
| R-06 | 手机号选填 |
| R-07 | 性别选填 |
| R-08 | 用户名不可重复，若已存在则返回错误"用户名已存在" |
| R-09 | 注册成功后自动完成登录，无需再次输入 |

**异常处理**：

| 异常场景 | 处理方式 |
|----------|----------|
| 用户名已存在 | 提示"该用户名已被注册，请更换" |
| 必填字段为空 | 前端表单校验拦截，提示对应字段为必填 |
| 后端服务不可用 | 提示"网络异常，请稍后重试" |

---

#### F-03：登录状态保持

**描述**：患者登录后，刷新页面或重新访问问诊页面时，无需重新登录。

**前置条件**：
- 患者已完成登录

**操作流程**：
1. 患者登录成功后，前端将登录信息存储到 localStorage
2. 访问问诊页面时，检查 localStorage 中是否有有效登录信息
3. 如有，自动恢复登录状态
4. 如无或信息无效，显示登录表单

**业务规则**：

| 规则编号 | 规则描述 |
|----------|----------|
| R-01 | 登录信息存储在 localStorage，key 为 `qa_patient` |
| R-02 | 存储内容包含：患者 ID、用户名、姓名等基础信息（不存储密码） |
| R-03 | 退出登录时清除 localStorage 中的患者信息 |

---

#### F-04：退出登录

**描述**：已登录患者点击"退出登录"按钮，清除登录状态，返回登录界面。

**前置条件**：
- 患者已登录

**操作流程**：
1. 患者点击问诊页面右上角的"退出登录"按钮
2. 清除前端存储的登录信息
3. 清除 store 中的 currentPatient
4. 页面切换为登录表单

## 4. 非功能需求

### 4.1 性能要求

| 指标 | 要求 |
|------|------|
| 登录接口响应时间 | < 1s |
| 注册接口响应时间 | < 1s |

### 4.2 安全要求

| 场景 | 要求 |
|------|------|
| 密码存储 | 后端使用 BCrypt 加密存储，禁止明文存储 |

| 前端存储 | localStorage 中不存储密码明文 |

### 4.3 兼容性要求

| 维度 | 要求 |
|------|------|
| 浏览器 | Chrome 90+、Firefox 90+、Edge 90+ |
| 设备 | 桌面端优先，移动端基本可用 |

## 6. 接口设计

### 6.1 接口清单

| 编号 | 方法 | 路径 | 描述 | 优先级 |
|------|------|------|------|--------|
| API-01 | POST | /api/patient/login | 患者登录 | P0 |
| API-02 | POST | /api/patient/register | 患者注册 | P0 |
| API-03 | GET | /api/patient/{id} | 获取患者信息 | P1 |

### 6.2 接口详细设计

#### API-01：患者登录

**请求**：
- 方法：`POST`
- 路径：`/api/patient/login`
- Content-Type：`application/json`

请求体：
```json
{
  "username": "patient-zhao-ming",
  "password": "123456"
}
```

**响应**：

成功响应（200）：
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "id": "patient001",
    "username": "patient-zhao-ming",
    "name": "赵明",
    "birthday": "1985-03-15",
    "phone": "138****1234",
    "gender": "男"
  }
}
```

失败响应：
| 状态码 | 错误码 | 描述 |
|--------|--------|------|
| 401 | AUTH_FAILED | 用户名或密码错误 |
| 500 | SERVER_ERROR | 服务器内部错误 |

---

#### API-02：患者注册

**请求**：
- 方法：`POST`
- 路径：`/api/patient/register`
- Content-Type：`application/json`

请求体：
```json
{
  "username": "patient-new-user",
  "password": "123456",
  "name": "新用户",
  "birthday": "1990-01-01",
  "phone": "138****0000",
  "gender": "男"
}
```

**响应**：

成功响应（200）：
```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "id": "patient006",
    "username": "patient-new-user",
    "name": "新用户",
    "birthday": "1990-01-01",
    "phone": "138****0000",
    "gender": "男"
  }
}
```

失败响应：
| 状态码 | 错误码 | 描述 |
|--------|--------|------|
| 400 | USERNAME_EXISTS | 该用户名已被注册 |
| 400 | PARAM_ERROR | 参数校验失败 |
| 500 | SERVER_ERROR | 服务器内部错误 |

---

#### API-03：获取患者信息

**请求**：
- 方法：`GET`
- 路径：`/api/patient/{id}`

**响应**：

成功响应（200）：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": "patient001",
    "username": "patient-zhao-ming",
    "name": "赵明",
    "birthday": "1985-03-15",
    "phone": "138****1234",
```

失败响应：
| 状态码 | 错误码 | 描述 |
|--------|--------|------|
| 404 | NOT_FOUND | 患者不存在 |
| 500 | SERVER_ERROR | 服务器内部错误 |

## 7. 页面/交互设计

### 7.1 页面清单

| 编号 | 页面名称 | 路由 | 描述 |
|------|----------|------|------|
| P-01 | 患者登录/注册 | /consultation | 在原问诊页面的身份验证区域改造 |

### 7.2 页面交互说明

#### P-01：患者登录/注册

**入口**：导航栏"在线问诊"、医生列表页"问诊"按钮、直接访问 `/consultation`

**页面元素**：

| 元素 | 类型 | 描述 |
|------|------|------|
| 标题 | 文字 | "患者登录"（登录态）/ "患者注册"（注册态） |
| 用户名输入框 | Input | 带用户图标前缀，placeholder "请输入用户名" |
| 密码输入框 | Password | 带锁图标前缀，placeholder "请输入密码" |
| 确认密码输入框 | Password | 仅注册态显示 |
| 姓名输入框 | Input | 仅注册态显示 |
| 生日选择器 | DatePicker | 仅注册态显示 |
| 手机号输入框 | Input | 仅注册态显示 |
| 性别选择 | Select | 仅注册态显示 |
| 登录/注册按钮 | Button | 主按钮，根据当前状态切换文字 |
| 切换链接 | Link | "没有账号？立即注册" / "已有账号？去登录" |
| 测试账号提示 | Alert | 登录态显示，提示测试账号信息 |

**交互流程**：

**登录流程**：
1. 默认显示登录表单（用户名 + 密码）
2. 输入用户名和密码，点击"登录"
3. 验证通过 → 进入问诊主界面
4. 验证失败 → 显示错误提示

**注册流程**：
1. 点击"没有账号？立即注册"，表单切换为注册模式
2. 填写注册信息，点击"注册"
3. 注册成功 → 自动登录，进入问诊主界面
4. 注册失败 → 显示错误提示

**已登录状态**：
1. 显示患者问诊主界面（与现有逻辑一致）
2. 右上角显示"退出登录"按钮
