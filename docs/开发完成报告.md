## 一、已完成功能概览

### 1. 前端中英文切换（FR-1）

- **语言资源**：`web/qa-web/src/locales/zh-CN.json`、`en.json` 存放首页全部文案，结构为 `home.*`。
- **切换组件**：首页（`Home.vue`）右上角**仅在本页**展示语言下拉菜单，选项为「中文」「English」，切换后首页文案**动态**更新，无需整页刷新。
- **状态管理**：`locales/index.ts` 提供 `useLocale()`（含 `locale`、`setLocale`、`t`），当前语言持久化到 `localStorage`。
- **验收**：语言切换控件仅在首页展示；问诊、医生、关于页不展示；资源文件仅存放在 `src/locales`。

### 2. 后端医生相关 API（FR-2、FR-3）

- **数据库**：
  - 项目根目录 **docker-compose.yml**：MySQL 8（库 `qa_healthcare`，用户 `qa_user`，端口 3306）+ phpMyAdmin（端口 8081），字符集 utf8mb4。
  - 表结构：**单表**小写 `doctor`，由 JPA `@Table(name = "doctor")` + `ddl-auto=update` 创建。
  - 初始数据：`server/qa-service-user/src/main/resources/data.sql` 使用 `INSERT IGNORE` 插入与原有 JSON 等效的 5 条医生记录。
- **数据访问层**：`DoctorRepository` 继承 `JpaRepository<Doctor, String>`，所有查询为参数化，防 SQL 注入。
- **业务逻辑层**：`DoctorService` 查询全部医生、将实体转为 `DoctorResponse`（解析 specialties JSON、**不暴露 password**）。
- **REST 接口**：`DoctorController` 提供 **GET /api/doctors**，`produces = "application/json;charset=UTF-8"`，返回医生数组，无 password。
- **配置**：`Utf8EncodingConfig` 强制响应 UTF-8；`CorsConfig` 允许前端来源；`application.properties` 中 datasource、JPA、`spring.jpa.defer-datasource-initialization=true` 与 `data.sql` 执行顺序正确。

### 3. 前后端联调（FR-4）

- **前端**：
  - 医生页（`Doctors.vue`）从 **GET /api/doctors** 获取列表（通过 store 在 App 挂载时 `fetchDoctors()`），展示头像、姓名、职称、科室、经验、专长、在线/离线；加载中显示 loading、失败显示错误信息与重试、空数组显示「暂无医生」。
  - 首页统计与开放诊室数据与同一 API 一致（`store.getStatistics()`、`store.getActiveDoctors()` 基于 `state.doctors`）。
  - Vite 配置 **proxy**：`/api` → `http://localhost:8080`，开发时无 CORS 问题。
- **医生登录**：仍使用本地密码映射（原 JSON 的 username→password）校验，不通过 API 暴露密码；登录后 `currentDoctor` 来自 API 返回的医生列表，保证与数据源一致。
- **中文**：后端响应头 `charset=UTF-8`、库表 utf8mb4、前端 UTF-8，医生页与 API 中文显示正常。

### 4. 测试与文档（FR-5、FR-6、FR-7）

- **API 测试脚本**：`scripts/test-doctors-api.sh`，使用 **curl** 请求 GET /api/doctors，校验状态码 200、响应为 JSON 数组、无 jq 时至少校验状态码与以 `[` 开头；有 jq 时校验不含 `password`。
- **API 测试说明**：项目根目录 **API_TEST.md**，说明环境准备、执行方式（`bash scripts/test-doctors-api.sh`）、预期结果、无 jq 时的验收方式，并引用《技术实现文档》二、数据库设计（双表排查）。
- **API 说明文档**：**docs/api.md**，覆盖 qa-service-user 全部 API（GET /api/doctors、GET/POST/OPTIONS /api/test/cors），含方法、路径、请求/响应、响应示例、错误码及测试说明或引用 API_TEST.md。

## 四、遇到的挑战与处理

1. **Doctor 实体缺失**：代码中已引用 `entity.Doctor`，但未创建。新增 `entity/Doctor.java`，字段与表结构规范一致，`specialties` 以 `specialtiesJson` 映射，由 Service 解析为 List。
2. **后端依赖**：pom.xml 原无 JPA 与 MySQL，已添加 `spring-boot-starter-data-jpa` 与 `mysql-connector-j`。
3. **data.sql 执行顺序**：需在 Hibernate 建表之后执行，已设置 `spring.jpa.defer-datasource-initialization=true`，并采用 `INSERT IGNORE` 避免重复启动报错。
4. **医生登录与 API 数据一致**：登录不能从 API 取密码，故保留本地 username→password 映射用于校验，`currentDoctor` 从 API 拉取的医生列表中取，保证展示与数据源一致；登录前若医生列表未加载会先执行 `fetchDoctors()`。
5. **Docker 拉取超时**：验收环境若遇网络问题导致 `docker-compose up -d` 拉取镜像超时，属环境问题；docker-compose 与后端配置已就绪，网络正常时按 API_TEST.md 顺序启动即可复现。
