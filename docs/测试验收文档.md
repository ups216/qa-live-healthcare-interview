## 二、测试环境与前置条件

### 2.1 环境要求

| 项目 | 要求 |
|------|------|
| 前端 | Node 18+，在 `web/qa-web` 执行 `npm install` 与 `npm run dev`，默认端口 5173 |
| 后端 | JDK 17，在 `server/qa-service-user` 执行 `./mvnw spring-boot:run` 或等价命令，端口 8080 |

## 四、API 测试（curl 与脚本）

### 4.1 医生列表 API 测试要点

| 检查项 | 说明 | 建议验证方式 |
|--------|------|--------------|
| 状态码 | GET /api/doctors 返回 200 | curl -w "%{http_code}" 或脚本中判断 |
| 响应体类型 | Content-Type: application/json | curl -I 或解析响应头 |
| 响应体结构 | 根为数组，元素为对象，含 id、username、name、title、department、avatar、experience、specialties、isActive | 人工查看或 jq 校验 |
| 无敏感字段 | 不包含 password | 人工或 jq 检查 |

### 4.2 建议的 curl 示例（可放入脚本或 API_TEST.md）

```bash
# 基础连通性
curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/api/doctors
# 预期输出: 200

# 获取并格式化输出（需 jq）
curl -s http://localhost:8080/api/doctors | jq .

# 检查为数组且至少一条（依赖 jq，可选）
curl -s http://localhost:8080/api/doctors | jq 'type == "array" and length > 0'
# 预期: true
```

**无 jq 时的验收**：若环境无 `jq`，脚本至少应校验 (1) HTTP 状态码为 200；(2) 响应 body 为非空且为合法 JSON（如通过 grep 或人工查看）。API_TEST.md 中建议注明「可选依赖 jq」及无 jq 时的执行与验收方式。

### 4.3 测试脚本与文档验收

| 验收项 | 说明 | 通过标准 |
|--------|------|----------|
| curl 测试脚本 | 位于 scripts/ 或约定位置 | 脚本可执行，覆盖 GET /api/doctors，且文档中说明执行方式 |
| API_TEST.md | 说明 API 测试如何执行 | 包含：环境准备、如何运行脚本、预期结果（状态码/响应示例） |
| docs/api.md | qa-service-user 的 **全部** API 说明 | 包含 GET /api/doctors 及 /api/test/cors（GET/POST/OPTIONS 等）的说明；每项含方法、路径、响应及测试说明（或引用 API_TEST.md） |
