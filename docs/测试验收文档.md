### 2.3 API 测试要点（curl/脚本）

| 检查项 | 说明 | 验证方式 |
|--------|------|----------|
| 状态码 | GET /api/doctors 返回 200 | curl -w "%{http_code}" 或脚本判断 |
| 响应体类型 | Content-Type: application/json；**建议 charset=UTF-8**（避免中文乱码） | curl -I 或解析响应头 |
| 响应体结构 | 根为数组，元素含规定字段 | 人工或 jq 校验 |
| 无敏感字段 | 不包含 password | 人工或 jq 检查 |

**无 jq 时**：脚本至少校验 (1) HTTP 状态码 200；(2) 响应 body 为非空且合法 JSON。API_TEST.md 中注明「可选依赖 jq」及无 jq 时的执行与验收方式。

## 三、自动化测试策略

### 3.1 分层策略

| 层级 | 范围 | 自动化方式 | 本阶段实施建议 |
|------|------|------------|----------------|
| API 层 | GET /api/doctors、/api/test/cors | **curl 脚本** + 可选 jq | **必须**：scripts/ 下可执行脚本，根目录 API_TEST.md 说明 |
| 交付物/结构 | 文件与目录存在性、文档内容 | 可选：脚本检查文件存在、grep 关键内容 | 建议：验收前人工或简单脚本核对 |
| UI/端到端 | 首页语言切换、医生页展示、**中文无乱码** | 可选：Playwright/Cypress | 本阶段不强制，以手工测试为主 |

### 3.2 curl 脚本自动化要点

- **位置**：`scripts/` 下（如 `scripts/test-doctors-api.sh`）。
- **内容**：至少对 GET /api/doctors 执行请求，校验 HTTP 200；可选校验 JSON 为数组、含关键字段、不含 password（依赖 jq 时）；可选校验响应头含 charset=UTF-8。
- **文档**：**项目根目录** API_TEST.md 中说明环境准备、执行方式（如 `bash scripts/test-doctors-api.sh`）、预期结果（状态码与示例响应）。
- **可重复性**：脚本需在「MySQL + qa-service-user 已启动」的前提下可重复执行并通过。

### 3.3 与 CI 的衔接（可选）

若后续接入 CI，可增加步骤：启动 Docker 与 qa-service-user（或 testcontainers）→ 执行 scripts 下 API 测试脚本 → 根据退出码判定通过/失败。本阶段不做强制要求。

## 五、性能测试方案

### 5.1 定位与范围

本阶段为**面试交付**，不要求生产级性能；性能测试为**可选/轻量**，用于验证在合理负载下服务可用、无明显瓶颈。

### 5.2 建议指标（可选）

| 指标 | 目标 | 说明 |
|------|------|------|
| GET /api/doctors 响应时间 | 单次请求 P95 < 500ms（本地） | MySQL 约 5～20 条数据、无其他负载时测量 |
| 并发 | 5～10 并发下无 5xx、无超时 | 可选：ab、wrk 或 curl 循环简单压测 |
| 前端首屏/医生页 | 无明显长时间白屏 | 依赖前端 loading 与接口响应，可手工观察 |

### 5.3 执行方式（可选）

1. **环境**：MySQL 与 qa-service-user 已启动，具备至少 5 条医生数据。
2. **工具**：`curl` 多次请求测延迟；或 `ab -n 100 -c 5 http://localhost:8080/api/doctors` 做轻量压测。
3. **通过标准**：无 5xx、P95 在可接受范围内（如 < 500ms 本地）；若未执行性能测试，不影响功能与交付物验收。

### 5.4 不在本阶段要求内

- 压力测试、稳定性长时间运行、数据库连接池与 JVM 调优、前端打包体积与首屏性能深度优化。
