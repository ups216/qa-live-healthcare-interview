## 1. 概述

### 1.1 背景
当前系统中，患者登录采用"姓名+生日"的验证方式，存在以下问题：
1. 安全性较低，生日信息容易被获取
2. 无法区分同名患者
3. 不符合常规用户系统的登录规范
4. 患者无法自主注册账号

### 1.2 目标
1. 为患者提供标准的用户名密码登录方式
2. 支持患者自主注册功能
3. 将患者数据从JSON文件迁移到MySQL数据库
4. 保持与现有医生登录体验的一致性

### 1.3 范围
**包含：**
- 患者注册页面
- 患者登录页面
- 患者数据表设计
- 后端注册/登录API
- 前端登录状态管理

**不包含：**
- 手机号验证码登录
- 第三方登录（微信、支付宝等）
- 密码找回功能（后续迭代）

## 3. 功能需求

### 3.1 功能列表
| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| FR-001 | 患者注册 | 患者填写信息创建账号 | P0 |
| FR-002 | 患者登录 | 使用用户名密码登录 | P0 |
| FR-003 | 退出登录 | 患者退出当前账号 | P0 |
| FR-004 | 登录状态持久化 | 刷新页面保持登录状态 | P1 |

### 3.2 详细设计

#### 3.2.1 患者注册
**描述：** 新患者创建账号

**输入：**
- 用户名：3-20位字母数字下划线，唯一
- 密码：6-20位字符
- 确认密码：与密码一致
- 姓名：2-20位中文
- 手机号：11位数字（可选）

**输出：**
- 注册成功：自动登录并跳转首页
- 注册失败：显示错误信息

**业务规则：**
1. 用户名不能重复
2. 两次密码必须一致
3. 注册成功后自动登录

**UI/UX 设计：**
- 页面路径：`/patient/register`
- 与医生登录页面风格一致
- 表单验证即时反馈

#### 3.2.2 患者登录
**描述：** 已注册患者登录系统

**输入：**
- 用户名
- 密码

**输出：**
- 登录成功：跳转首页，显示用户信息
- 登录失败：显示错误信息

**业务规则：**
1. 用户名或密码错误显示统一提示
2. 登录成功后存储token到localStorage
3. 登录状态保持7天

**UI/UX 设计：**
- 页面路径：`/patient/login`
- 与医生登录页面布局一致
- 提供注册链接

## 4. 非功能需求

### 4.1 性能要求
- 登录接口响应时间 < 500ms
- 支持100并发登录请求

### 4.2 安全要求
- 密码传输使用HTTPS加密
- 密码存储使用BCrypt加密
- 登录失败不提示具体错误原因

### 4.3 兼容性要求
- 支持Chrome、Firefox、Safari最新版本
- 支持移动端响应式布局

## 5. 数据设计

### 5.1 数据模型

**patients 表**
```
patients
- id: VARCHAR(20), PRIMARY KEY, 患者ID
- username: VARCHAR(50), UNIQUE NOT NULL, 用户名
- password: VARCHAR(100), NOT NULL, 加密密码
- name: VARCHAR(50), NOT NULL, 姓名
- phone: VARCHAR(20), 手机号
- gender: VARCHAR(10), 性别
- birthday: DATE, 出生日期
- created_at: TIMESTAMP, 创建时间
- updated_at: TIMESTAMP, 更新时间
```

### 5.2 API 设计
| 方法 | 路径 | 描述 | 请求参数 | 响应 |
|------|------|------|----------|------|
| POST | /api/patients/register | 患者注册 | {username, password, name, phone} | {id, username, name} |
| POST | /api/patients/login | 患者登录 | {username, password} | {id, username, name, token} |
| GET | /api/patients/{id} | 获取患者信息 | - | {id, username, name, phone} |
