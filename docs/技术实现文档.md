### 1.2 技术栈（与本需求相关）

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | Vue 3 + TypeScript + Vite | 保持现有，首页增加 i18n、医生页改为 API 拉取 |
| 前端 i18n | 自建 locales 或 vue-i18n | 资源文件固定放在 `web/qa-web/src/locales` |

| 数据库 | MySQL 8.x | 由 docker-compose 提供，端口可 3306 |
| 管理界面 | phpMyAdmin | 同 docker-compose 挂接，便于查看数据 |

## 二、需求一：首页中英文切换

### 2.1 目录与文件约定

- 语言资源目录：**`web/qa-web/src/locales`**
- 建议文件：
  - `zh-CN.ts` 或 `zh.ts`：中文
  - `en.ts`：英文
  - `index.ts`：导出当前语言与 `t(key)` 或供 i18n 使用的结构

### 2.2 首页文案 Key 建议（与 Home.vue 对应）

| 文案位置 | 中文示例 | 建议 Key（示例） |
|----------|----------|------------------|
| 主标题 | 专业在线医疗问诊平台 | `home.hero.title` |
| 副标题 | 连接专业医生与患者... | `home.hero.subtitle` |
| 特性 1 | 专业医生团队 | `home.hero.feature1` |
| 特性 2 | 实时在线问诊 | `home.hero.feature2` |
| 特性 3 | 隐私安全保护 | `home.hero.feature3` |
| 按钮 | 立即问诊 / 查看医生 | `home.hero.btnConsult` / `home.hero.btnDoctors` |
| 统计 | 专业医生 / 问题总数 / 待响应问题 / 在线诊室 | `home.stat.doctors` 等 |
| 开放诊室 | 开放诊室 / 以下医生诊室正在开放... | `home.rooms.title` / `home.rooms.subtitle` |
| 诊室卡片按钮 | 进入诊室 | `home.rooms.enter` |

实现时在 Home.vue 中用 `t('home.hero.title')` 等形式替换硬编码中文；英文资源提供对应 English 文案。

### 2.3 语言切换控件

- **位置**：首页右上角（可与 AppHeader 结合：仅首页显示语言下拉，或 Header 全局显示但仅首页响应切换）。无论控件放在 Home 内还是 AppHeader 内，**需求范围仅限首页文案切换**，其他页面不要求多语言。
- **实现方式**：  
  - 若仅首页需要 i18n：可在 Home.vue 内维护 `locale` 状态，下拉选择后切换 `locale`，首页从 `locales[locale]` 取文案。  
  - 若使用 vue-i18n：在 App 或 main 中挂载 i18n，语言切换调用 `locale = 'en'` / `'zh-CN'` 等，首页使用 `$t()` 或 `useI18n().t()`。
- **选项**：下拉选项为「中文」「English」，与需求一致。

### 2.4 实现步骤（建议顺序）

1. 在 `web/qa-web/src/locales` 下新增 `zh-CN.ts`、`en.ts`（及可选 `index.ts`）。
2. 在 Home.vue 中引入 locales，用响应式变量保存当前语言。
3. 将 Home.vue 中所有需国际化的文案改为从 locales 按 key 读取。
4. 在首页右上角增加语言选择下拉，切换时更新当前语言并触发首页重渲染。
5. **首页数据依赖**：首页有「统计」与「开放诊室」区块，当前依赖 `store.getStatistics()` 与 `store.getActiveDoctors()`（即 store 中的 doctors 与 questions）。医生数据改为 API 后，须保证首页能拿到医生数据，可选方案：(a) 在 App 或根组件挂载时请求 `GET /api/doctors` 并写入 `store.state.doctors`，供首页与医生页共用；(b) 在 Home.vue 的 onMounted 中请求医生列表并写入 store 或本地状态，仅首页使用。否则统计数字与开放诊室列表会为空。

## 三、需求二与三：医生数据、API 与联调

### 3.1 数据模型：医生（与前端 Doctor 对齐）

前端 `store` 中已有 `Doctor` 接口，API 与数据库需与之兼容。**列表接口可不返回 password**。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 是 | 唯一标识，如 doc001 |
| username | string | 是 | 登录用，如 dr-zhang-wei |
| name | string | 是 | 显示名，如 张伟医生 |
| title | string | 是 | 职称，如 主任医师 |
| department | string | 是 | 科室 |
| avatar | string | 是 | 头像 URL |
| experience | string | 是 | 经验描述 |
| specialties | string[] | 是 | 专长列表，JSON 数组或逗号分隔入库后序列化 |
| isActive | boolean | 是 | 是否在线 |
| password | string | 可选 | 仅后端/登录用，列表 API 不返回 |

### 3.2 数据库设计（MySQL）

**表名建议**：`doctor`

| 列名 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(32) PK | 主键 |
| username | VARCHAR(64) UNIQUE NOT NULL | 登录名 |
| password | VARCHAR(255) | 密码（可明文或后续加密） |
| name | VARCHAR(128) NOT NULL | 姓名 |
| title | VARCHAR(64) | 职称 |
| department | VARCHAR(64) | 科室 |
| avatar | VARCHAR(512) | 头像 URL |
| experience | VARCHAR(128) | 经验 |
| specialties | JSON 或 VARCHAR(500) | 专长（JSON 数组序列化）。MySQL 8.x 推荐用 JSON 类型；若用 VARCHAR 存 JSON 字符串，需在实体层做序列化/反序列化，且长度需容纳数组字符串。 |
| is_active | TINYINT(1) / BOOLEAN | 是否在线，默认 1 |

初始化脚本或 Flyway/Liquibase 可放在 qa-service-user 的 `src/main/resources/db` 或项目根目录 `scripts/`，由团队约定。

### 3.3 docker-compose 约定

- **文件位置**：**项目根目录** **`docker-compose.yml`**（与需求分析、测试验收文档一致）。
- **服务**：
  - **mysql**：镜像 `mysql:8`，端口 3306，挂载数据卷（可选），设置 `MYSQL_ROOT_PASSWORD`、`MYSQL_DATABASE`（如 `qa_user`）。
  - **phpmyadmin**：镜像 `phpmyadmin`，依赖 mysql，端口 8082 或 80，配置 `PMA_HOST=mysql`。
- 应用配置：qa-service-user 的 `application.properties` 或 `application.yml` 中配置 `spring.datasource.url=jdbc:mysql://localhost:3306/qa_user` 等，与 compose 中数据库名、端口一致。
- **启动顺序**：必须先启动 MySQL（`docker-compose up -d`），再启动 qa-service-user，否则应用连接数据库失败。

### 3.4 qa-service-user API 设计

**基础路径**：`/api`（与现有 `/api/test` 一致风格）。

| 方法 | 路径 | 说明 | 响应 |
|------|------|------|------|
| GET | /api/doctors | 医生列表（供前端 Doctors 页使用） | 200 OK，Body 为 Doctor 数组（不含 password） |

**GET /api/doctors**

- **请求**：无必填参数；可选 `activeOnly=true` 仅返回在线医生（若本期未实现可忽略）。
- **响应**：`Content-Type: application/json`，Body 示例：
```json
[
  {
    "id": "doc001",
    "username": "dr-zhang-wei",
    "name": "张伟医生",
    "title": "主任医师",
    "department": "心内科",
    "avatar": "https://...",
    "experience": "15年临床经验",
    "specialties": ["高血压", "冠心病", "心律失常"],
    "isActive": true
  }
]
```
- **与前端一致**：字段名与 store 中 `Doctor` 及 Doctors.vue 使用一致（如 `isActive` 驼峰），避免前端再做字段映射。
- **错误响应**：当数据库异常或服务异常时，建议返回 HTTP 500 及统一错误结构（如 `{"message": "..."}`），便于前端与 curl 脚本判断；具体格式可由实现决定。
- **CORS/OPTIONS**：前端直连 8080 时浏览器会发 OPTIONS 预检，现有 `CorsConfig` 已做全局 CORS 配置，`/api/doctors` 的 OPTIONS 由该配置统一处理，无需单独为 /api/doctors 再写 OPTIONS 方法。

### 3.5 后端实现要点（qa-service-user）

1. **依赖**：增加 `spring-boot-starter-data-jpa` 或 MyBatis + `mysql-connector-j`，以及可选 flyway/liquibase。
2. **配置**：`application.properties` 中配置数据源（URL、用户名、密码），与 docker-compose 中 MySQL 一致。
3. **实体**：`Doctor` 实体映射表 `doctor`，字段与上表对应，`specialties` 可用 `@Convert` 或 VARCHAR 存 JSON 字符串。
4. **Repository**：`DoctorRepository` 继承 JpaRepository 或 MyBatis Mapper，提供 `findAll()`。
5. **Controller**：`DoctorController` 或 `DoctorsController`，`GET /api/doctors` 调用 repository，将实体转为 DTO（去掉 password），返回 List。
6. **CORS**：已有 CorsConfig，若前端直连 8080，需保证允许前端 origin；开发阶段可为 `*` 或指定 `http://localhost:5173`。

### 3.6 前端联调（医生列表页）

1. **数据获取**：Doctors.vue 或 store 中不再从 `doctor-user-list.json` 加载医生列表；改为在挂载时请求 `GET http://localhost:8080/api/doctors`（或通过 Vite 代理 `/api` → `http://localhost:8080`，则请求 `/api/doctors`）。
2. **代理（可选）**：在 `vite.config.ts` 中配置：
   - `server.proxy['/api'] -> target: 'http://localhost:8080'`，前端统一请求同源 `/api/doctors`，避免 CORS 配置问题。
3. **状态**：可将医生列表存于 store（如 `state.doctors`），由 Doctors 页或 App/根组件在进入应用或首页时请求并写入（这样首页的统计与开放诊室也能用到）；或仅在 Doctors.vue 内用 `ref` + `onMounted` 请求并渲染（此时首页若依赖医生数据，需在 Home 或 App 中单独请求医生列表，见 2.4 节）。
4. **错误处理**：需求要求当 API 返回非 2xx 或空数组时页面不崩溃且有可识别反馈。实现时：请求失败（网络错误、5xx）可展示「加载失败」等提示；返回 200 且 body 为 `[]` 时可展示「暂无医生」或空状态，具体文案与样式可与产品约定。

### 3.7 实现步骤（建议顺序）

1. 在项目根目录新增 **docker-compose.yml**，启动 MySQL + phpMyAdmin。
2. 在 qa-service-user 中增加数据源、JPA/MyBatis、Doctor 实体与表结构（含初始化数据或 data.sql）。
3. 实现 **GET /api/doctors**，返回不含 password 的医生列表，并用 Postman/curl 自测。
4. 前端：在 Doctors 页或 store 中调用该 API，替换原 JSON 数据源；必要时配置 Vite 代理。
5. 联调：按顺序启动——(1) MySQL（docker-compose up -d）；(2) qa-service-user；(3) 前端；验证医生列表页展示、首页统计与开放诊室、以及「进入诊室」等功能。

## 四、测试与文档（实现侧）

### 4.1 curl 测试脚本

- **位置**：**`scripts/`** 目录，如 `scripts/test-doctor-api.sh` 或 `scripts/api-test.sh`（与需求、测试文档一致）。
- **内容**：至少包含对 `GET /api/doctors` 的 curl 调用，检查 HTTP 200；可选检查 JSON 为数组、含关键字段、不含 password。若使用 `jq` 做结构校验，建议在 API_TEST.md 中注明「可选依赖 jq」；无 jq 时脚本至少校验状态码与 body 非空。
- **可执行性**：若为 `.sh`，需在 API_TEST.md 中说明执行方式（如 `bash scripts/test-doctor-api.sh` 或 `sh scripts/test-doctor-api.sh`）；在 Windows 下可用 Git Bash 或说明用 `curl` 手动执行文档中的命令。
- **约定**：脚本内 BASE_URL 可配置为 `http://localhost:8080`，并在 API_TEST.md 中说明「先启动 MySQL 与 qa-service-user」。

### 4.2 API_TEST.md

- **位置**：**项目根目录** **API_TEST.md**（README 未指定路径，三份文档统一约定为根目录，便于验收对照）。
- **内容**：环境准备（先启动 MySQL，再启动 qa-service-user）、如何执行 curl 脚本（如 `bash scripts/xxx.sh`）、预期结果（状态码、响应示例）、可选的手动 curl 示例；若脚本依赖 jq，注明可选安装方式或提供无 jq 时的验收步骤。

### 4.3 docs/api.md

- **位置**：**`/docs/api.md`**。
- **内容**：qa-service-user **全部** 对外 API 的说明（与 README「所有 api 测试进行说明」一致），包括：
  - **GET /api/doctors**：医生列表，请求/响应、示例；以及如何测试（或引用 API_TEST.md）。
  - **GET /api/test/cors**、**POST /api/test/cors**、**OPTIONS**（若文档中需区分）：现有 CORS 测试接口的说明及测试方式。
