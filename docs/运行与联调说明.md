# 运行与联调说明

本文档说明如何按正确顺序启动各组件并完成前后端联调（不修改 README 本身）。

## 脚本启动（推荐）

项目根目录下提供以下可执行脚本（`scripts/` 目录），可从任意目录执行：

| 脚本 | 说明 |
|------|------|
| `./scripts/start-infra.sh` | 启动 MySQL + phpMyAdmin（docker-compose），等待约 10 秒 |
| `./scripts/start-backend.sh` | 启动 qa-service-user（需先执行 start-infra.sh） |
| `./scripts/start-frontend.sh` | 安装依赖并启动前端开发服务 |
| `./scripts/start-all.sh` | 从零启动全部服务：先清理旧容器与数据卷，再启动基础设施 → 后端后台 → 前端后台，日志输出到 `scripts/logs/` |

一键从零启动（会先执行 `docker-compose down -v` 再启动，避免旧 MySQL 数据卷导致 Access denied）：`./scripts/start-all.sh`。

## 启动顺序（手动）

1. **MySQL + phpMyAdmin**（项目根目录）
   ```bash
   docker-compose up -d
   ```
   等待约 10 秒后，phpMyAdmin：http://localhost:8082 ，MySQL：localhost:3306

2. **qa-service-user**（后端）
   ```bash
   cd server/qa-service-user
   ./mvnw spring-boot:run
   ```
   就绪后：http://localhost:8080

3. **前端**（web/qa-web）
   ```bash
   cd web/qa-web
   npm install
   npm run dev
   ```
   默认：http://localhost:5173 ，通过 Vite 代理将 `/api` 转发到 8080

## 联调验证

- **首页**：打开 http://localhost:5173/ ，右上角语言切换（仅首页），统计与开放诊室应有数据。
- **医生页**：打开 http://localhost:5173/doctors ，列表来自 `GET /api/doctors`，可点击「进入诊室」。
- **API 测试**：执行 `bash scripts/test-doctor-api.sh`，参见 [API_TEST.md](../API_TEST.md)。

## 常见问题

- **后端启动报错 `Access denied for user 'qa_app'@'...'`**：多为 MySQL 数据卷为旧配置导致。使用 `./scripts/start-all.sh` 时会自动先执行 `docker-compose down -v` 再启动，可避免此问题；若仅手动执行了 `start-infra.sh`，可先执行 `docker-compose down -v` 后再执行 `./scripts/start-infra.sh`（会清空数据库数据）。
- **医生页一直「加载医生列表中」**：确认 qa-service-user 已启动且 MySQL 已就绪；若后端返回 500，前端会展示 body 中的 `message`。
- **开放诊室为空**：首页依赖 `store.doctors`，需先等 App 挂载时 `fetchDoctors()` 完成；若 API 失败，统计与开放诊室会为空。
