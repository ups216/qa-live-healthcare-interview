## 三、功能测试过程与结果

### 3.1 首页中英文切换（FR-1，用例 F1.0～F1.8）

| 用例编号 | 验收项 | 结果 | 说明 |
|----------|--------|------|------|
| F1.0 | 语言切换控件**仅在首页**展示 | 通过 | `AppHeader.vue` 无语言控件；`Home.vue` 内 `.hero-lang` 仅在本页，问诊/医生/关于页不渲染该区块 |
| F1.1 | 首页右上角语言切换**下拉菜单** | 通过 | `Home.vue` 使用 `a-dropdown` + `a-menu`，位于 hero 区域右上角 |
| F1.2 | 选项包含「中文」「English」 | 通过 | `a-menu-item key="zh-CN"` 与 `key="en"`，文案分别为「中文」「English」 |
| F1.3 / F1.4 | 选择中文/English 后首页文案对应切换 | 通过 | 使用 `useLocale()` 的 `t('home.xxx')`，zh-CN.json / en.json 覆盖标题、副标题、特性、按钮、统计、开放诊室等 |
| F1.5 | 切换语言**动态**生效，无需整页刷新 | 通过 | `setLocale(key)` 更新 `currentLocale`，Vue 响应式使 `t()` 即时更新 |
| F1.6 | 语言资源**仅**在 `web/qa-web/src/locales` | 通过 | 存在 `locales/index.ts`、`zh-CN.json`、`en.json`，无其他目录存放首页 i18n 资源 |
| F1.7 | 仅首页多语言，其他页面可不做 | 通过 | 问诊、医生、关于页未做 i18n，符合要求 |
| F1.8 | 首页统计与开放诊室数据与 API 一致 | 通过 | `store.getStatistics()`、`store.getActiveDoctors()` 均基于 `state.doctors`，数据来自 `fetchDoctors()` → GET /api/doctors |

**结论**：首页中英文切换相关 P0 用例均通过，代码与配置符合《测试验收文档》要求。建议在浏览器中人工复核：首页切换「中文」/「English」后文案即时变化，且问诊/医生/关于页不出现语言切换控件。

### 3.2 医生数据与 API（FR-2、FR-3，用例 F2.1～F2.5）

| 用例编号 | 验收项 | 结果 | 说明 |
|----------|--------|------|------|
| F2.1 | 根目录 docker-compose 可启动 MySQL 与 phpMyAdmin | 通过 | 根目录存在 `docker-compose.yml`，已执行 `docker compose up -d`，容器运行正常 |
| F2.2 | 仅一张医生表 `doctor`，至少 5 条记录 | 通过 | JPA `@Table(name = "doctor")`，schema.sql / data.sql 与 Hibernate 一致；data.sql 中 INSERT 5 条医生 |
| F2.3 | GET /api/doctors 返回 200 | 通过 | 实际请求：`curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/api/doctors` 输出 **200** |
| F2.4 | 响应为医生数组、结构正确、**不包含 password** | 通过 | 响应为 JSON 数组；字段含 id、username、name、title、department、avatar、experience、specialties、isActive；`DoctorResponse` 无 password 字段；脚本在安装 jq 时校验不含 password |
| F2.5 | 响应数据与库中一致（含 specialties 序列化） | 通过 | `DoctorService.toResponse()` 将 `specialtiesJson` 解析为 `List<String>` 写入 DTO；data.sql 中中文专长与响应一致（如「高血压」「冠心病」「心律失常」） |

**API 响应头与编码**：  
- 实际响应头：`Content-Type: application/json;charset=UTF-8`（DoctorController 已设置 `produces = "application/json;charset=UTF-8"`）。  
- 响应体抽样：`"name":"张伟医生","title":"主任医师","department":"心内科"` 等中文正常，无乱码。  

**结论**：医生数据与 API 相关 P0 用例通过，编码与数据正确。

### 3.3 医生列表前后端联调（FR-4，用例 F3.1～F3.8）

| 用例编号 | 验收项 | 结果 | 说明 |
|----------|--------|------|------|
| F3.1 | 医生页列表数据来自 GET /api/doctors | 通过 | `store.fetchDoctors()` 请求 `/api`（Vite 代理到 8080），Doctors.vue 使用 `store.state.doctors` |
| F3.2 | 医生卡片信息完整展示 | 通过 | 卡片展示头像、姓名、职称、科室、经验、专长、在线/离线（a-badge）；字段与 API 一致 |
| F3.3 | 点击在线医生「进入诊室」跳转正常 | 通过 | `router.push(\`/consultation/${doctor.username}\`)`，路由为 `/consultation/:doctorUsername`，Consultation.vue 通过 `route.params.doctorUsername` 调用 `store.getDoctorByUsername()` 展示诊室 |
| F3.4 | 离线医生「暂未开放」或按钮不可用 | 通过 | `:disabled="!doctor.isActive"`，按钮文案 `doctor.isActive ? '进入诊室' : '暂未开放'` |
| F3.5 | 对 /api/doctors 无 CORS 报错 | 通过 | 开发环境 Vite proxy 将 `/api` 转发至 8080，同源请求无 CORS；后端 CorsConfig + application.properties 已配置 CORS |
| F3.6 | 加载中/请求失败时有反馈，不白屏 | 通过 | `doctorsLoading` 时显示 a-spin +「加载中...」；`doctorsError` 时显示 a-alert + 重试按钮 |
| F3.7 | API 返回空数组时「暂无医生」空状态 | 通过 | `v-else-if="!store.state.doctors.length"` 时渲染 `a-empty description="暂无医生"` |
| F3.8 | 医生页中文正常、无乱码；API charset=UTF-8；表 utf8mb4 | 通过 | API 已设置 charset=UTF-8；MySQL docker 与 JPA 表为 utf8mb4；index.html 含 `charset="UTF-8"`；后端 Utf8EncodingConfig + server.servlet.encoding 已配置 |

**结论**：前后端联调及中文编码相关 P0 用例均通过。
