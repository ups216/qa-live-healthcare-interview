## 1. 产品概述

### 1.1 产品简介

本产品是一款面向医疗机构的在线问诊平台，旨在为患者提供便捷的远程问诊服务，同时帮助医生高效管理患者信息和诊疗记录。问诊用户登录功能是平台的基础能力，为用户提供安全可靠的身份认证服务。

### 1.2 产品目标

- 为问诊用户提供安全、便捷的用户名密码登录方式
- 确保用户身份认证的安全性和数据保护
- 支持登录状态的会话管理

### 1.3 产品范围

- **患者端**：用户名密码登录、退出登录、登录状态保持
- **本功能范围**：仅包含问诊用户（患者）的用户名密码登录，不包含用户注册、医生登录、管理员登录

---

## 2. 需求背景

### 2.1 业务背景

随着在线问诊服务的普及，用户对登录方式的安全性和便捷性要求越来越高。用户名密码登录作为一种经典的身份认证方式，具有用户熟悉度高、无需额外设备支持等优势，是在线问诊平台必备的基础功能。

### 2.2 问题陈述

- 用户需要一个安全可靠的身份认证入口进入问诊系统
- 平台需要识别已登录用户，以提供个性化服务和问诊记录
- 需要防止未授权访问，保护用户隐私和诊疗数据

### 2.3 解决思路

通过实现用户名密码登录功能，为问诊用户提供标准化的身份认证服务。采用 JWT Token 机制实现无状态会话管理，结合密码加密存储和安全防护措施，确保登录安全。

### 5.2 详细功能说明

#### 5.2.1 用户名密码登录

**功能描述**：
问诊用户通过输入用户名和密码进行身份认证，认证成功后获取访问令牌进入系统。

**业务规则**：
- 用户名字段：支持字母、数字、下划线，长度 4-20 个字符
- 密码字段：支持字母、数字、特殊字符，长度 6-20 个字符
- 密码必须加密存储（BCrypt）
- 连续 5 次密码错误，锁定账号 10 分钟
- 登录成功后生成 JWT Token，有效期 24 小时
- Token 刷新机制：支持在 Token 过期前刷新

**交互流程**：
1. 用户进入登录页面
2. 用户输入用户名和密码
3. 前端进行基础校验（非空、格式）
4. 前端提交登录请求到后端
5. 后端验证用户名密码
6. 验证成功后生成 JWT Token 并返回
7. 前端存储 Token，跳转至首页
8. 页面展示用户登录状态

**页面原型**：参考前端页面设计

**接口说明**：

| 接口名称 | 请求方式 | 请求路径 | 说明 |
|----------|----------|----------|------|
| 用户登录 | POST | /api/auth/login | 用户名密码登录 |
| 退出登录 | POST | /api/auth/logout | 清除登录状态 |
| Token刷新 | POST | /api/auth/refresh | 刷新访问令牌 |

**数据字典**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | String | 是 | 用户名 |
| password | String | 是 | 密码（传输时加密） |

#### 5.2.2 退出登录

**功能描述**：
用户主动退出登录，清除本地登录状态和会话信息。

**业务规则**：
- 退出时清除本地存储的 Token
- 后端记录退出日志
- 退出后跳转至首页或登录页

**交互流程**：
1. 用户点击退出登录按钮
2. 前端清除本地 Token
3. 前端跳转至首页
4. 后端记录退出日志（如已配置）

## 7. 异常处理

### 7.1 通用异常处理

| 异常类型 | HTTP状态码 | 错误码 | 错误信息 | 用户提示 |
|----------|------------|--------|----------|----------|
| 系统异常 | 500 | SYS_001 | 系统内部错误 | 操作失败，请稍后重试 |
| 参数错误 | 400 | PARAM_001 | 参数校验失败 | 请检查输入信息 |
| 认证失败 | 401 | AUTH_001 | Token无效或已过期 | 请重新登录 |
| 权限不足 | 403 | AUTH_002 | 无访问权限 | 您没有权限执行此操作 |
| 资源不存在 | 404 | RES_001 | 请求资源不存在 | 信息不存在或已被删除 |

### 7.2 登录模块异常处理

| 异常场景 | 错误码 | 错误信息 | 处理建议 |
|----------|--------|----------|----------|
| 用户名不存在 | AUTH_101 | 用户名或密码错误 | 统一提示，防止遍历用户名 |
| 密码错误 | AUTH_101 | 用户名或密码错误 | 统一提示，提示剩余次数 |
| 连续错误锁定 | AUTH_102 | 账号已锁定，请10分钟后再试 | 显示锁定倒计时 |
| 账号已禁用 | AUTH_103 | 账号已被禁用，请联系管理员 | 提示联系管理员 |
| Token过期 | AUTH_104 | 登录已过期 | 跳转至登录页面 |
| Token格式错误 | AUTH_105 | Token格式错误 | 跳转至登录页面 |

### 7.3 前端异常处理

| 场景 | 处理方式 |
|------|----------|
| 网络请求失败 | 显示重试按钮，提示"网络连接失败，请检查网络" |
| 接口超时 | 30秒超时，显示"请求超时，请稍后重试" |
| 表单校验失败 | 实时校验，红色提示错误信息 |
| 登录失败 | 显示统一错误提示，不区分具体原因 |

### B. API 接口设计

#### 登录接口

```
POST /api/auth/login
Content-Type: application/json

Request:
{
  "username": "string",
  "password": "string"
}

Response (成功):
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "jwt_token_string",
    "tokenType": "Bearer",
    "expiresIn": 86400,
    "userInfo": {
      "id": 1,
      "username": "user001",
      "status": 1
    }
  }
}

Response (失败):
{
  "code": 401,
  "message": "用户名或密码错误",
  "data": {
    "remainingAttempts": 4
  }
}
```

#### 退出登录接口

```
POST /api/auth/logout
Authorization: Bearer {token}

Response:
{
  "code": 200,
  "message": "退出成功",
  "data": null
}
```

#### Token刷新接口

```
POST /api/auth/refresh
Authorization: Bearer {token}

Response:
{
  "code": 200,
  "message": "刷新成功",
  "data": {
    "token": "new_jwt_token_string",
    "tokenType": "Bearer",
    "expiresIn": 86400
  }
}
```
