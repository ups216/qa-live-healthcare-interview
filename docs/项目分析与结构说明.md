# 项目分析与结构说明

## 一、项目概述

本项目为 **QA 在线医疗问诊面试项目**（qa-live-healthcare-interview），用于面试场景下的编码/测试/文档实践。项目模拟一个医疗问诊系统，包含前端 Web 应用与多个后端微服务，当前部分功能以前端 JSON 静态数据为主，部分后端服务已搭建框架，可按 README 中的技术要求进行扩展（如首页中英文切换、医生数据迁入 MySQL 并对外提供 API 等）。

**核心业务场景：**

- 患者浏览医生列表、选择医生进入诊室进行问诊
- 医生登录、进入诊室处理患者问题
- 问诊与问答数据在前端 store 中维护（当前为 JSON + 内存状态）

### 4.2 .asdm 工具集

为项目内建的规范与动作定义，不参与业务运行：

- **basic-tools**：Git 提交、提交信息等规范与动作。
- **context-builder**：架构、API、数据模型、部署、编码风格、项目结构等规范。
- **prd-builder**：PRD 规划、拆解与执行相关动作与规范。

### 4.3 server（后端服务）

| 服务名                 | 说明 | 端口 | 状态 |
|------------------------|------|------|------|
| qa-service-user       | 用户/医生服务，提供 CORS 与测试接口 | 8080 | 已实现基础框架，待接医生列表 API 与 MySQL |
| qa-service-question   | 问诊/问题服务 | 8081 | 仅启动类，无业务接口 |
| qa-service-statistic  | 统计服务     | -    | 预留目录，未实现 |

**qa-service-user 当前实现要点：**

- **技术**：Spring Boot 3.5.7、Java 17、spring-boot-starter-web、actuator。
- **配置**：`application.properties` 中配置了 CORS、Actuator 端点、应用信息。
- **代码**：
  - `config/CorsConfig.java`：全局 CORS，支持前后端分离调用。
  - `controller/TestController.java`：`/api/test/cors` 的 GET/POST/OPTIONS，用于验证 CORS。
- **测试**：含基础应用测试；面试要求中需补充医生列表相关 API 及 curl 测试脚本。

**qa-service-question：**

- 仅 `QaServiceQuestionApplication` 启动，端口 8081，无 Controller 或业务逻辑。

### 4.4 web/qa-web（前端）

- **技术**：Vue 3（Composition API + `<script setup>`）、TypeScript、Vite、Vue Router、Ant Design Vue、dayjs。
- **入口**：`index.html` → `main.ts` → `App.vue`，布局为顶部 `AppHeader` + 中部 `RouterView` + 底部 `AppFooter`。
- **路由**（`src/router/index.ts`）：

| 路径 | 名称 | 说明 |
|------|------|------|
| `/` | Home | 首页 |
| `/doctors` | Doctors | 医生列表（需对接后端医生 API） |
| `/consultation`、`/consultation/:doctorUsername` | Consultation | 问诊入口/指定医生诊室 |
| `/about` | About | 关于页 |
| `/doctor/login` | DoctorLogin | 医生登录 |
| `/doctor/room/:username` | DoctorRoom | 医生诊室 |

- **状态**（`src/store/index.ts`）：  
  当前从 `src/data/*.json` 加载医生、患者、问题列表，并在内存中维护当前医生/患者、问诊与问答状态。医生列表页面 `Doctors.vue` 使用 `store.state.doctors`，面试要求改为从 qa-service-user 的 API 获取。
- **静态数据**（`src/data/`）：
  - `doctor-user-list.json`：医生列表（id、username、name、title、department、avatar、experience、specialties、isActive 等）。
  - `patient-user.json`：患者信息。
  - `question-list.json`：问诊/问题列表。

## 五、数据流与前后端关系（当前与目标）

**当前：**

- 前端：医生、患者、问题数据均来自本地 JSON + store，无后端 API 调用（除可选的 CORS 测试）。
- 后端：qa-service-user 仅提供 `/api/test/cors`，未提供医生列表等业务 API。

**目标（按 README 要求）：**

- 使用 MySQL 存储医生相关数据，docker-compose 提供 MySQL + phpMyAdmin。
- qa-service-user 提供支持「医生页面」所需的医生列表 API，前端 Doctors 页改为调用该 API。
- 首页增加中英文切换，语言资源放在 `web/qa-web/src/locales`。
- 使用 curl 编写医生列表相关 API 的测试脚本，并配合 `API_TEST.md`、`/docs/api.md` 说明。

## 七、小结
