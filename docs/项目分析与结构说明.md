## 二、缺失项汇总表

| 序号 | 缺失项 | 位置/说明 | 优先级 | 备注 |
|------|--------|-----------|--------|------|
| 1 | **docker-compose.yml** | 项目根目录 | P0 | 用于创建 MySQL 与 phpMyAdmin；文档多处引用，当前工作区未找到。 |
| 2 | **Doctor 实体类** | `server/qa-service-user/.../entity/Doctor.java` | P0 | Repository/Service 已引用 `entity.Doctor`，文件缺失会导致编译失败。 |
| 3 | **data.sql** | `server/qa-service-user/src/main/resources/data.sql` | P0 | 数据库说明中约定用于向表 `doctor` 插入至少 5 条初始数据。 |
| 4 | **MySQL/JPA 配置** | `application.properties` | P0 | 当前仅有 CORS、Actuator 等，缺少 `spring.datasource.*` 与 `spring.jpa.*`（如 ddl-auto、defer-datasource-initialization）。 |
| 5 | **start-all.sh** | `scripts/start-all.sh` | P1 | 文档中描述的一键启动 Docker + 后端 + 前端的脚本，便于本地联调。 |
| 6 | **fix-duplicate-doctor-table.sh** | `scripts/` | P2 | 数据库说明中用于删除重复医生表、统一字符集。 |

**说明**：若实际运行环境与上述扫描结果不一致（例如实体与 data.sql 已存在或通过其他分支/本地存在），以实际工作区与可运行状态为准。

## 三、现有代码结构分析

### 3.1 后端 qa-service-user

| 层级 | 现状 | 说明 |
|------|------|------|
| **Controller** | DoctorController（GET /api/doctors）、TestController（/api/test/cors） | 医生列表接口已定义，响应 `application/json;charset=UTF-8`。 |
| **Service** | DoctorService | 依赖 `DoctorRepository` 与 `entity.Doctor`，完成实体转 DTO、specialties JSON 解析。 |
| **Repository** | DoctorRepository extends JpaRepository<Doctor, String> | 依赖缺失的 `entity.Doctor`。 |
| **DTO** | DoctorResponse | 含 id、username、name、title、department、avatar、experience、specialties、isActive，无 password。 |
| **Entity** | **缺失** | 文档约定为 `@Entity`、`@Table(name = "doctor")`，与 JPA 建表一致。 |
| **Config** | CorsConfig、Utf8EncodingConfig | 跨域与 UTF-8 编码。 |
| **Exception** | GlobalExceptionHandler | 统一异常处理。 |
| **Resources** | application.properties 无数据源；data.sql 缺失 | 需补全数据源、JPA 及初始化数据。 |

### 3.2 前端 qa-web

| 模块 | 现状 | 说明 |
|------|------|------|
| **Store** | 从 `data/doctor-user-list.json` 静态导入医生数据 | 若需与后端联调，应改为在适当时机请求 GET /api/doctors 并写入 state。 |
| **首页** | Home.vue 使用 store.getStatistics()、store.getActiveDoctors() | 统计与开放诊室依赖 store 中的 doctors，若 store 改为 API 拉取则与后端一致。 |
| **医生页** | Doctors.vue 使用 `store.state.doctors` | 同上，需保证数据来源为 API 或与 API 一致。 |
| **国际化** | locales 目录含 zh-CN.json、en.json、index.ts | 首页中英文切换所需资源已具备；需确认首页是否已接入并仅首页展示语言切换。 |
| **路由/视图** | 问诊、医生、关于、诊室、医生登录等 | 结构完整。 |

### 3.3 其他服务

- **qa-service-question**：仅 Spring Boot 入口与基础测试，本阶段不在测。
- **qa-service-statistic**：仅占位目录，无实现。

## 五、技术实现复杂度评估

| 维度 | 评估 | 说明 |
|------|------|------|
| **后端 CRUD/API** | 低 | 仅医生列表查询，无写接口；Controller/Service/Repository/DTO 已就绪，补实体与配置即可。 |
| **数据库与编排** | 低 | 单表 doctor、标准 MySQL 镜像 + 环境变量；docker-compose 配置简单。 |
| **前端联调** | 中 | 需将医生数据源从 JSON 切到 API，并处理 loading/错误/空状态（需求与验收文档已要求）。 |
| **国际化** | 低 | 资源文件已有，仅首页展示语言切换并绑定 locales 即可。 |
| **测试与文档** | 已就绪 | scripts/test-doctors-api.sh、API_TEST.md、docs/api.md 已存在，可按验收查漏补缺。 |

**整体**：在补全缺失实体、配置与数据脚本后，后端可快速打通；前端改为消费 /api/doctors 并做好状态与错误处理即可满足当前面试范围。
