## 一、功能需求分析表

| 需求编号 | 需求名称 | 需求描述 | 来源 | 优先级 |
|----------|----------|----------|------|--------|
| FR-1 | 首页中英文切换 | 在 Web 端**首页**右上角添加**语言切换下拉菜单**，用户选择 **中文** 或 **English** 时**动态切换**页面显示内容到对应语言。中英文语言资源文件**必须**保存在 `web/qa-web/src/locales` 目录中。**只处理首页本身**，无需处理其他页面（问诊、医生、关于等）。 | README 编码要求 1 | P0 |
| FR-2 | 医生数据 MySQL 存储 | 将当前存于前端 JSON 的医生数据迁移至 MySQL。在**项目根目录**创建 **docker-compose.yml**，用于创建 MySQL 数据库，并**挂接 phpMyAdmin** 作为数据库服务器管理界面。 | README 编码要求 2 | P0 |
| FR-3 | 医生列表 API | 在 **qa-service-user** 服务中创建可支持前端 [医生页面](web/qa-web/src/views/Doctors.vue) **显示医生列表**所需的 API，返回数据满足列表展示所需字段，且**不暴露** password 等敏感信息。 | README 编码要求 2 | P0 |
| FR-4 | 前后端联调 | 前端医生页从上述 API 获取医生列表并正确展示；首页统计与开放诊室等与医生相关的数据与 API 数据源一致；前后端联调无 CORS 等问题；医生页中文显示正常、无乱码。 | README 编码要求 2、《项目分析与结构说明》 | P0 |
| FR-5 | API 测试脚本 | **使用 curl** 构建针对**医生列表页面所依赖的 API** 的测试用例脚本，脚本置于 **scripts/** 下，可执行（如 `bash scripts/xxx.sh`）。 | README 测试要求 1 | P0 |
| FR-6 | API 测试说明文档 | 在**项目根目录**提供 **API_TEST.md**，用于说明上述 API 测试的**执行方式**与**预期结果**。 | README 测试要求 2 | P0 |
| FR-7 | API 说明文档 | 生成 **/docs/api.md** 文档，用于对 **qa-service-user 服务中的所有 API** 进行说明（含医生列表 API 与现有 /api/test/cors 等），并包含测试说明或引用 API_TEST.md。 | README 文档要求 1 | P0 |
| FR-8 | 特性分支与 PR | **创建特性分支**（自己命名），在分支内完成编码、测试与文档编写；完成后将分支**推送到自己代码库**，并**基于分支创建指向 main 的 PR**，发送 PR 链接。 | README 分支要求、面试流程要求 | P0 |
| FR-9 | AI Coding 与时效 | 以上编码、测试、文档**全部使用 AI Coding 提示词方式完成**，不得直接编码（可对 AI 产出进行手工调整）。面试者需在 **2 天内**完成整个流程。 | README 面试流程要求、面试时间要求 | P0 |

## 二、非功能需求说明

| 类别 | 需求编号 | 需求描述 | 验收方式 |
|------|----------|----------|----------|
| **可维护性** | NFR-1 | 语言资源与代码分离，中英文文案**仅**存放在 `web/qa-web/src/locales`，便于后续扩展语言或修改文案。 | 目录与文件结构检查 |
| **安全性** | NFR-2 | 医生列表 API 响应中**不得包含** password 等敏感字段。 | API 响应体检查 / 脚本或 jq 校验 |
| **兼容性** | NFR-3 | 前端支持现代浏览器（Chrome/Firefox/Safari/Edge 近期版本）；后端 JDK 17、Spring Boot 3.x；Node 18+。 | 环境与依赖说明 |
| **可用性** | NFR-4 | 医生页在加载中、空列表、请求失败时应有明确反馈（loading/空状态/错误提示），不白屏、不未处理异常崩溃。 | 功能测试用例 F3.6、F3.7 |
| **可测性** | NFR-5 | 医生列表 API 需可通过 **curl 脚本**在本地复现验证；脚本不强制依赖 jq，无 jq 时至少校验状态码与合法 JSON。 | API_TEST.md 与脚本执行 |
| **可读性/编码** | NFR-6 | 医生页与 API 响应**中文显示正常、无乱码**；API 响应头 Content-Type 建议为 `application/json;charset=UTF-8`，数据库表使用 utf8mb4。 | 测试用例 F3.8、API 响应头与表字符集检查 |
| **交付时效** | NFR-7 | 面试者需在 2 天内完成编码、测试与文档，并完成 PR。 | 流程约束 |
| **流程约束** | NFR-8 | 所有编码/测试/文档需通过 AI Coding 提示词方式完成，允许对 AI 产出进行人工调整。 | 流程约束 |

### 3.1 访客（未登录用户）

| 故事 ID | 用户故事 | 验收标准摘要 |
|---------|----------|--------------|
| US-1 | 作为**访客**，我希望在**首页**右上角切换语言（中文/English），以便用自己熟悉的语言浏览首页。 | 切换后首页文案即时变为对应语言；**仅首页**展示语言切换控件；资源文件位于 `src/locales`。 |
| US-2 | 作为**访客**，我希望在「医生」页看到来自**后端 API** 的医生列表，以便了解当前可咨询的医生。 | 列表与 GET /api/doctors 一致，展示头像、姓名、职称、科室、经验、专长、在线状态；**中文无乱码**。 |

## 四、验收标准定义

以下验收项与《测试验收文档》中的用例编号（F1.x、F2.x、F3.x、F4.x）一一对应，便于需求与测试追溯。

### 4.1 需求一：首页中英文切换（FR-1）

| 验收项 ID | 验收标准 | 优先级 |
|-----------|----------|--------|
| AC1.0 | 语言切换控件**仅在首页**展示；问诊、医生、关于等页**不展示**该控件。 | P0 |
| AC1.1 | 首页右上角存在语言切换**下拉菜单**，选项为「中文」「English」。 | P0 |
| AC1.2 | 选择「中文」后，首页所有需国际化的文案（标题、副标题、特性、按钮、统计、开放诊室等）显示为**中文**。 | P0 |
| AC1.3 | 选择「English」后，上述文案显示为**英文**。 | P0 |
| AC1.4 | 切换语言后文案**动态**更新，无需整页刷新。 | P0 |
| AC1.5 | 中英文资源文件**仅**存放在 `web/qa-web/src/locales`，且可被正确引用。 | P0 |
| AC1.6 | 仅首页要求多语言；其他页面可不做 i18n。 | P2 |
| AC1.7 | 首页统计数字与开放诊室列表与数据源一致，不长期空白或错乱；**数据源指 GET /api/doctors 或与之一致的后端接口**。【评审意见】明确数据源定义，便于与实现（首页调用同一 API）闭环，避免歧义。 | P0 |

### 4.2 需求二：医生数据与 API（FR-2、FR-3）

| 验收项 ID | 验收标准 | 优先级 |
|-----------|----------|--------|
| AC2.1 | 项目**根目录**存在 **docker-compose.yml**，可启动 MySQL 与 phpMyAdmin。 | P0 |
| AC2.2 | MySQL 中**仅存在一张**医生表，表名为**小写** `doctor`，且至少有 **5 条**与原有 JSON 等效的医生记录；若存在两张表需按《技术实现文档》二、数据库设计及相关说明排查。【评审意见】《数据库说明》当前在 docs 下不存在，统一改为引用《技术实现文档》二、数据库设计。 | P0 |
| AC2.3 | qa-service-user 提供 **GET /api/doctors**，返回 HTTP 200，Content-Type 为 application/json（建议 **charset=UTF-8** 避免中文乱码）。 | P0 |
| AC2.4 | 响应为 JSON 数组，每项包含 id、username、name、title、department、avatar、experience、specialties、isActive 等前端所需字段，且**不包含** password。 | P0 |
| AC2.5 | 响应数据与数据库中对应记录一致（含 specialties 等正确序列化）。 | P1 |

### 4.3 需求三：医生列表前后端联调（FR-4）

| 验收项 ID | 验收标准 | 优先级 |
|-----------|----------|--------|
| AC3.1 | 前端医生页（/doctors）展示的列表与 GET /api/doctors 返回数据一致。 | P0 |
| AC3.2 | 医生卡片正确展示头像、姓名、职称、科室、经验、专长标签、在线/离线状态。 | P0 |
| AC3.3 | 点击在线医生「进入诊室」跳转到对应诊室路由（如 /consultation/:username），无报错。 | P0 |
| AC3.4 | 离线医生显示为离线，「暂未开放」或按钮不可用。 | P1 |
| AC3.5 | 对 /api/doctors 的请求无 CORS 相关报错。 | P0 |
| AC3.6 | 加载中或请求失败时有 loading/「加载失败」等反馈，不白屏不崩溃。 | P0 |
| AC3.7 | API 返回空数组时，页面展示「暂无医生」或空状态提示，不报错。 | P1 |
| AC3.8 | **医生页姓名、职称、科室等中文显示正常、无乱码**；API 响应头含 charset=UTF-8，表 doctor 为 utf8mb4。 | P0 |
