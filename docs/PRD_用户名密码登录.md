## 1. 需求背景与目标

### 1.1 需求背景
系统存在两类使用角色——**医生**（提供在线问诊）与**患者**（接受问诊）。当前两者的登录均通过前端本地 JSON 模拟（`store.loginDoctor` / `store.verifyPatient`），用户名 / 密码与校验逻辑暴露在浏览器端，存在安全隐患，且无法在多端 / 多服务间统一鉴权。需要实现真实的服务端登录，区分角色并签发 JWT。

### 1.2 产品目标
- 实现医生端、患者端的服务端登录，替代前端本地 JSON 模拟。
- 登录成功后返回有效期 **2 小时**的 JWT；JWT 过期后拒绝访问并引导重新登录。
- 明确**哪些入口触发医生登录、哪些入口触发患者登录**，避免角色混淆。
- 为后续受保护接口（医生诊室、患者问诊、问答等）提供统一的身份认证基础。

## 2. 需求范围与优先级

### 2.1 范围界定

| ✅ 本版本做（In Scope） | ❌ 本版本不做（Out of Scope） |
| --- | --- |
| 医生登录（用户名 + 密码，MD5 比对） | 注册、找回密码、修改密码 |
| 患者登录（姓名 + 出生日期，首次自动建档） | 第三方登录（微信 / OAuth 等） |
| 登录成功签发 JWT（有效期 2h，含角色） | 权限分级 / 细粒度 RBAC（仅区分医生、患者两类） |
| JWT 校验与过期处理（拦截器，只校验过期） | 多端 / App 端登录（本期仅 Web） |
| 各入口的登录类型区分与跳转 | 受保护业务接口的具体实现（问诊 / 诊室，后续需求） |

## 3. 用户与场景

### 3.1 角色
| 角色 | 描述 | 凭证 | 权限 |
| --- | --- | --- | --- |
| 医生 | 使用用户名 + 密码登录，进入医生端工作台（诊室、问答） | username + password（校验 `doctors` 表，密码 MD5） | 医生相关受保护接口 |
| 患者 | 使用姓名 + 出生日期登录，进入问诊 / 诊室；**首次输入自动创建账户** | name + birthday（校验 / 写入 `patients` 表） | 患者相关受保护接口 |

### 3.2 核心用户故事
| 编号 | 用户故事 | 优先级 |
| --- | --- | --- |
| US-01 | 作为医生，我希望用用户名和密码登录，以便进入医生端工作台 | P0 |
| US-02 | 作为患者，我希望输入姓名和出生日期即可使用（首次自动建档、再次相同信息登录），以便进入问诊 / 诊室 | P0 |
| US-03 | 作为任一角色，当登录凭证过期时，我希望被引导重新登录，以便继续安全使用 | P0 |

### 3.3 登录入口与触发规则（关键）

> **核心约束**：**医生登录仅发生在「首页点击医生登录」时**；其余所有需要身份的入口（问诊、进入诊室）均为**患者登录**。

| 「医生登录」按钮 | 首页 | **医生登录** | 跳转医生登录页，登录后进入医生端工作台 |
| 顶部导航「问诊」 | 顶部导航栏 | 患者登录 | 跳转患者登录页，登录后进入问诊页 |
| 首页「立即问诊」 | 首页 Hero 区 | 患者登录 | 跳转患者登录页，登录后进入问诊页 |
| 首页医生卡片「进入诊室」 | 首页开放诊室 | 患者登录 | 跳转患者登录页，登录后进入对应诊室 |
| 医生团队页医生卡片「进入诊室」 | `/doctors` 页面 | 患者登录 | 跳转患者登录页，登录后进入对应诊室 |

## 4. 功能需求详述

### 4.1 功能：医生登录

#### 4.1.1 功能概述
- **一句话描述**：医生在首页点击「医生登录」，提交用户名和密码，服务端校验 `doctors` 表（密码 MD5 比对）通过后签发 JWT（有效期 2 小时，role=DOCTOR）。
- **优先级**：P0

#### 4.1.2 入口与前置条件
- **功能入口**：首页「医生登录」按钮 → 医生登录页（`DoctorLogin.vue`）
- **前置条件**：医生账号已存在于 `doctors` 表（由 `sql/data.sql` 初始化，密码为 MD5）

#### 4.1.3 交互与操作流程
| 步骤 | 用户操作 | 系统响应 | 页面 / 数据变化 |
| --- | --- | --- | --- |
| 1 | 输入用户名、密码，点击登录 | 前端 `POST /api/auth/login`（type=doctor） | 等待响应 |
| 2 | — | 服务端 MD5 比对 `doctors` 表凭证 | 校验通过则生成 JWT（role=DOCTOR） |
| 3 | — | 返回 JWT 与医生基本信息 | 前端存储 token（localStorage）并跳转医生端工作台 |
| 4 | 后续请求 | 前端携带 `Authorization: Bearer <token>` | 服务端校验通过放行 |

#### 4.1.4 业务规则
- **凭证校验**：对输入密码做 MD5，与 `doctors` 表中该用户 `password` 比对。
- **JWT**：HS256 签名，载荷含 `username` / `role=DOCTOR`，`exp = 签发时间 + 2h（7200 秒）`。

#### 4.1.5 异常与边界
| 异常场景 | 系统表现 | 兜底 / 恢复方案 |
| --- | --- | --- |
| 用户名不存在 | 返回 401，提示"用户名或密码错误" | 引导重新输入 |
| 密码错误（MD5 不匹配） | 返回 401，提示"用户名或密码错误" | 引导重新输入 |
| JWT 过期 / 无效 | 受保护接口返回 401 | 前端清除 token，跳转登录页 |
| 服务不可用 | 登录接口超时 | 前端提示"服务异常，请重试" |

#### 4.1.6 验收标准
| 编号 | 场景 | 操作 | 预期结果 | 优先级 |
| --- | --- | --- | --- | --- |
| AC-01 | 正确凭证 | 提交正确用户名密码 | 返回 JWT，role=DOCTOR，`exp` 在 2h 内 | P0 |
| AC-02 | 错误凭证 | 提交错误密码 | 返回 401，提示凭证错误 | P0 |
| AC-03 | 过期 token | 用过期 JWT 访问医生接口 | 返回 401，前端跳转登录页 | P0 |
| AC-04 | 无 token | 直接访问医生接口 | 返回 401 | P0 |

### 4.2 功能：患者登录

#### 4.2.1 功能概述
- **一句话描述**：患者在「问诊 / 进入诊室」等入口触发登录，输入**姓名与出生日期**，服务端按 `(name, birthday)` 查询 `patients` 表；不存在则自动建档，存在则直接登录，随后签发 JWT（有效期 2 小时，role=PATIENT）。
- **优先级**：P0

#### 4.2.2 入口与前置条件
- **功能入口**：顶部导航「问诊」、首页「立即问诊」、首页 / 医生团队页医生卡片「进入诊室」（见 3.3）
- **前置条件**：无需预置数据；首次输入姓名 + 出生日期即自动创建账户（与页面提示「输入任意姓名和生日即可使用。首次输入会自动创建账户，再次输入相同信息即可登录」一致）

#### 4.2.3 交互与操作流程
| 步骤 | 用户操作 | 系统响应 | 页面 / 数据变化 |
| --- | --- | --- | --- |
| 1 | 在未登录状态下点击上述任一患者入口 | 前端跳转患者登录页 | 展示姓名 + 出生日期表单 |
| 2 | 输入姓名、出生日期，点击登录 | 前端 `POST /api/auth/login`（type=patient） | 等待响应 |
| 3 | — | 服务端按 `(name, birthday)` 查 `patients`；无则 Insert 建档 | 生成 JWT（role=PATIENT） |
| 4 | — | 前端存储 token 并回跳原入口目标页（问诊 / 诊室） | 进入目标页 |

#### 4.2.4 业务规则
- **凭证校验**：以 `(name, birthday)` 作为唯一身份标识；不校验密码。
- **自动建档**：首次出现的 `(name, birthday)` 组合写入 `patients` 表并登录；再次输入相同信息直接登录。
- **JWT**：HS256 签名，载荷含 `username`（取姓名）/ `role=PATIENT`，`exp = 签发时间 + 2h`。

#### 4.2.5 异常与边界
| 异常场景 | 系统表现 | 兜底 / 恢复方案 |
| --- | --- | --- |
| 姓名 / 出生日期为空 | 返回 400，提示"姓名和出生日期不能为空" | 引导补全 |
| JWT 过期 / 无效 | 受保护接口返回 401 | 前端清除 token，跳转患者登录页 |
| 服务不可用 | 登录接口超时 | 前端提示"服务异常，请重试" |

#### 4.2.6 验收标准
| 编号 | 场景 | 操作 | 预期结果 | 优先级 |
| --- | --- | --- | --- | --- |
| AC-05 | 首次登录 | 输入任意姓名 + 出生日期 | 自动建档并返回 JWT，role=PATIENT | P0 |
| AC-06 | 再次登录 | 输入相同姓名 + 出生日期 | 直接登录并返回 JWT，不重复建档 | P0 |
| AC-07 | 过期 token | 用过期 JWT 访问患者接口 | 返回 401，前端跳转患者登录页 | P0 |

### 4.3 功能：JWT 校验（服务端拦截器，只校验过期）
- **实现位置**：`JwtInterceptor`（Spring `HandlerInterceptor`）。
- **校验内容**：解析 JWT（解析时一并验证签名，防止伪造），核心业务判断是 **`exp` 是否过期**；过期 / 无效 / 缺失一律返回 401。
- **白名单（免鉴权）**：现有接口对应的页面不登录也能访问，已在拦截器注册时排除：
  - `/api/doctors/**`（医生列表 / 活跃医生，公开）
  - `/api/auth/**`（登录接口本身，公开）
  - `/api/test/**`（测试接口，公开）
- **受保护接口**：后续需要登录的问诊 / 诊室接口（不在白名单的 `/api` 路径）将**自动**受 JWT 过期校验保护，无需逐个标记。
- **角色约束**：本期拦截器只做"是否过期"的通用校验；`role=DOCTOR` / `role=PATIENT` 的越权访问由具体业务接口自行判断（或后续增强拦截器）。

## 5. 非功能需求

### 5.1 安全
- JWT 使用服务端密钥（HS256）签名，密钥通过配置项管理（`jwt.secret`），禁止硬编码泄露。
- 响应中不返回 `password` 字段（`@JsonIgnore`）；患者本身无密码字段。
- token 有效期严格 2 小时，过期即失效，必须重新登录。
- 医生密码统一以 **MD5** 存储（基础防护，非高安全级别）；患者身份仅以姓名 + 出生日期标识，安全性较低，后续可升级为手机号 + 验证码。

### 5.2 性能
- 登录接口响应时长 P95 ≤ 300ms。

## 6. 接口与数据需求

### 6.1 接口清单
| 接口名称 | 调用方 | 请求方式 | 关键入参 | 关键出参 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 登录（通用） | 前端 | `POST /api/auth/login` | type,（医生）username+password /（患者）name+birthday | token, expiresIn, role, user | 无需鉴权；后端按 type 决定医生/患者逻辑 |
| 鉴权（拦截器） | 前端 | 各受保护接口 | Header: `Authorization: Bearer <token>` | 200 / 401 | 白名单接口免校验；其余校验 JWT 是否过期 |

### 6.2 登录接口示例

医生登录：
```json
POST /api/auth/login
Content-Type: application/json

{ "type": "doctor", "username": "dr-zhang-wei", "password": "123456" }
```

患者登录（首次自动建档 / 再次直接登录）：
```json
POST /api/auth/login
Content-Type: application/json

{ "type": "patient", "name": "张三", "birthday": "1990-05-20" }
```

成功响应（200，两种登录结构一致，仅 `role` 与 `user` 不同）：
```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9.xxxxx",
  "expiresIn": 7200,
  "role": "DOCTOR",
  "user": {
    "id": "doc001",
    "username": "dr-zhang-wei",
    "name": "张伟医生"
  }
}
```

失败响应（401 / 400）：
```json
{ "message": "用户名或密码错误" }
```

### 6.3 数据依赖
- **医生登录**：依赖 `doctors` 表（`username`、`password` 字段，密码为 MD5），由 `sql/data.sql` 初始化。
- **患者登录**：依赖 `patients` 表（`name`、`birthday`，`(name, birthday)` 唯一），**无初始数据**；首次登录自动写入（见 `sql/schema.sql`）。

## 7. 风险与应对
| 风险描述 | 概率 | 影响 | 应对 / 缓解措施 |
| --- | --- | --- | --- |
| JWT 密钥泄露 | 低 | 高 | 密钥配置化管理，定期轮换 |
| 医生密码仅 MD5 存储，存在彩虹表风险 | 中 | 中 | 后续需求改为加盐哈希（bcrypt / Argon2） |
| 患者身份仅以姓名+生日标识，易被冒用 | 中 | 中 | 明确其为低安全级别身份标识；后续可升级为手机号+验证码 |
| 医生 / 患者登录入口混淆导致跳转错误 | 中 | 低 | 严格按 3.3 入口触发规则实现与测试 |
